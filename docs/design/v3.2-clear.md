# Design v3.2: Clear theme (rev 3, flat Apple x Shopify)

Owner: Design. Status: **proposal for founder review, 2026-10-28, revision 3**. Nothing in this change touches app code. Clear is a second theme over the same structure as v3.1 Main Street Warm: same shell, same Today cards, same pages, same copy.

**History.** Rev 1 (flat neutral, Inter, indigo accent) was called "too bland". Rev 2 (frosted glass, mesh backdrop, Plus Jakarta Sans) was rejected: "No gradients, no AI slop elements. Think about something that would come out if Apple and Shopify had a baby." This page is rev 3 and replaces the values of rev 1 and rev 2. Rev 1 and rev 2 stay in Figma (pages "v3.2 Clear theme", "v3.3 Clear glass") for history.

**Figma:** [Local Loyalty v3 design system](https://www.figma.com/design/tat1lWRQIJ2Q3Al98pWOtA), page **v3.4 Clear** ([page link](https://www.figma.com/design/tat1lWRQIJ2Q3Al98pWOtA?node-id=49-2)). Frames: Today 1440 light (`50:2`), Today 1440 dark (`50:290`), Today 390 (`50:578`), customers index table with sheet and toast (`51:2`), counter tablet (`51:486`), customer pass (`51:617`). Collection `Clear v3.4 / Color` (37 variables, Light and Dark, with alpha for the four translucent chrome and segmented roles). The dark Today frame is the light frame in the Dark mode. Text is editable Inter; icons are Lucide vectors. Figma cannot set tabular figures through its plugin API, so the Figma frames show proportional digits; the HTML mock sets `tnum`.

**HTML mock and PNGs (scratch, not committed):** `/tmp/claude-0/-home-user-set-it-up-ai/5a1e2619-40bd-5f60-81fb-50d449557f59/scratchpad/clear/v3/`: `mock.html` (open with `?s=today|today-m|customers|counter|pass|promos|fonts`, `&t=dark`, `&l=ur`, `&f=geist`), `contrast.js` and `cc.py` (the AA check), PNG renders, `refs/` (20 Mobbin screenshots) and `research/` (Polaris tokens, HIG text, apple.com CSS extracts).

## 1. The direction

Take Apple's precision and Shopify's usefulness; remove everything that is only decoration.

- **From Apple:** a flat system-grey canvas, large confident titles with tight tracking, generous alignment discipline, real system-style controls (a segmented control with a white selected segment and a 1px shadow, a quiet blue for links and the active tab, a Wallet-style white pass), and translucency only on chrome: the sidebar, the top bar and the phone tab bar. HIG says it directly: materials belong to the navigation layer; "Don't use Liquid Glass in the content layer."
- **From Shopify (Polaris):** white cards with a 1px hairline and a 1px shadow, a dense but clear card header and row rhythm, an index table with checkboxes, a filter toolbar and a bulk-action bar, a black primary button, small crisp status badges, toasts that sit bottom-centre, and empty states with a title, one sentence and an action. The values below are Polaris's own tokens (section 2).
- **Banned and absent:** gradients (none, anywhere), glows and coloured shadows, glass cards, blur outside chrome, purple or indigo accent, sparkle icons, emoji, pill-everything, sparklines on every card, "☀️" copy, hero areas, stock illustration. Every element carries information or an action.
- **Colour means something:** black is the primary action; blue is a link or focus; green, amber and red are Polaris-style badges; the trade colour is the shop mark (the rounded square with the initials) and the stamps on the pass; everything else is grey.

What changed against Warm: the awning, the serif, the pastel tiles, the coloured Quick action tiles, the terracotta button, the trade gradient on the pass. What did not change: sidebar items and order, top bar contents, every label and number on Today, the "Needs you" rows, the page order, the counter flow, the pass content.

Small adaptations, not new information: the four Today stats are one metrics card with dividers (Polaris Analytics and Shopify Orders both use this); "Visits by hour" gets a Today / Week segmented control where Warm showed the word "Today"; the phone's Quick actions become a grouped list with chevrons, as iOS grouped lists do; the peak bar is ink with the peak label in bold.

## 3. Type

**Inter, with the display optical size for titles.** Reasons: Inter is the closest free match to SF Pro (a neutral grotesk with the same proportions and a variable optical-size axis that plays the role of SF Display versus Text); Shopify's admin uses Inter (the Polaris font stack is `'Inter', -apple-system, BlinkMacSystemFont, 'San Francisco', ...`), so users of both already read it; it is already the app body font (`--font-inter`), so there is nothing new to download; it has tabular figures (`tnum`), which the stat numbers, table counts, times and keypad need; and the existing Noto fallbacks for Hindi, Punjabi and Urdu keep following it. Geist was compared side by side with Inter on Today (`clear-font-compare.png`); at this density the two are almost the same, and Geist has no Indic or Arabic-script coverage. Plus Jakarta Sans (rev 2) is dropped: it is rounder and softer, which is the opposite of precise.

Inter's variable `opsz` axis (14 to 32) is switched on (`font-optical-sizing: auto`), so text sizes get the text cut and 26px titles get the display cut. Weights follow Polaris's variable-font values: regular 450, medium 550, semibold 650, bold 700 (`font-weight-regular: 450` and so on in Polaris tokens), so `font-weight: 450 / 550 / 650` in CSS (400 / 500 / 600 where the font is static). Letter-spacing follows SF's own tracking table (HIG Typography): -0.022em at 26px, -0.014em at 17, -0.011em at 14, -0.006em at 13, 0 at 12.

## 4. Components

- **Card with title and actions** (Polaris): white, 12 radius, 1px `--border`, 1px shadow; header 14 / 16 padding with the title left and an action (a segmented control, a text link or a slim button) right; rows divided by hairlines, not by space.
- **Metrics card:** one card, four cells divided by hairlines; label (13, 550, muted), number (26, 650), caption (12, 550; green only when it is an increase). No sparklines.
- **Index table** (Polaris IndexTable): toolbar with a segmented control (All 67, Regulars 30, ...) and Search, Filter, Sort buttons; a bulk-action bar that replaces nothing but sits under the toolbar when rows are selected (a mixed checkbox, "1 selected", Text, Add stamp, More actions); header row 12 / 550 muted on a hover-tint fill; 52px rows; checkbox column 44; selected row tinted `--row-sel`; hover row tinted `--accent`; badges for status; no avatars-with-colour (initials on grey).
- **Badges** (Polaris): 20px high, 8 radius, 12 / 550, no dot; neutral (grey), info (blue tint), success (green), warning (amber), critical (red). "Can text", "Live", "Reward ready", "Reward".
- **Segmented control** (Apple): `--seg-track`, 9 radius, selected segment white with a 1px shadow; used for Today / Week, the customer filters and the counter increments (larger).
- **Sheet:** 440 wide, flush to the right edge, `--background` body with white cards inside (like Shopify's customer detail page, in a drawer), flat 20% scrim with no blur, `--shadow-float`.
- **Toast** (Polaris): dark `#303030` rounded-8 bar, 13 / 550 text, an "Undo" action and a close icon, bottom centre of the content area.
- **Empty state** (Polaris): inside a card, a 40px grey icon chip, a 16 / 600 title, one sentence of concrete advice, a primary and a secondary button, a "Learn more" link below the card (`clear-empty-state-1440.png`, Promos).
- **Primary button:** black, 8 radius, no shadow; in dark it is white with black text. **Secondary:** white, 1px `--border-strong`, 1px shadow.
- **Phone tab bar** (iOS): translucent `--chrome`, 1px top border, 24px icons, 10px labels, the active tab in `--link`. This is one of the three translucent surfaces.
- **Pass** (Apple Wallet): a white card, 12 radius; top row with the shop mark (trade colour), the name and a "2 to go" badge; two rows of ten-stamp circles, filled in trade colour with a white coffee glyph, the next stamp a trade-coloured ring with a dot, empty stamps a hairline ring; below a hairline, three labelled fields (STAMPS, NEXT REWARD, MEMBER SINCE) in the Wallet field style. No gradient, no shadow.
- **Counter:** a solid, flat screen: white left panel with the phone field and keypad (white keys, 1px hairline, 1px shadow), the stamp card on the grey canvas, black primary buttons at 56px high. No translucency anywhere on the counter except the header, which uses `--chrome` as a flat fill.

## 5. Dark mode

Same roles, values in the tables. Rules: the canvas is near-black `#101012` and cards are `#1C1C1E` (Apple systemGray6-dark), separated by a 1px `#38383A` border and no shadow; the primary is white with black text (as Polaris does); links are `#2997FF`; badge text is lifted (`#6AE08A`, `#FFB340`, `#FF6961`, `#6CB8FF`) on 16% tints; the chart's current bar is white and the rest `#3A3A3C`; the trade colour is lifted to lightness 64 and the shop mark takes dark text.

## 6. Urdu RTL

Verified at 390 and 1440 (`clear-today-ur-390.png`, `clear-today-ur-1440.png`). Logical properties only (`padding-inline`, `margin-inline-start`, `inset-inline-end`, `border-inline-start`, `text-align: start`), so the sidebar goes to the right, the sheet slides from the left, the toast mirrors, the segmented control, metrics card, table columns and tab bar reverse; directional icons flip (`chevron-right`, arrows); the hour chart reverses with the page; Latin names and number runs inside Urdu lines sit in `<bdi>`; Nastaliq needs height, so line-height 1.95 and no fixed heights on rows or badges. Urdu strings new to this theme (the Segmented "Today / Week" labels, a few captions) need a native review. The Urdu render covers Today only.

## 7. Switching themes in the build

`data-theme-style` attribute on `<html>` (absent means Warm; `"clear"` means Clear); light and dark stay on `data-theme`. In `packages/design-tokens` (build team, not part of this change):

1. New `src/clear.ts` beside `warm.ts` holding the values in section 2 and `clearTradeColors(family, theme)` returning `{ accent, foreground, alt: accent, soft: muted, deep: accent }`.
2. In `css.ts` emit the third block set under `:root[data-theme-style="clear"]` for light and the two dark selectors, plus the 14 `[data-trade]` rules scoped the same way. The attribute selector sits in front, so it beats Warm without `!important`.
3. Fonts: leave `--font-sans` as Inter; set `--font-display` and `--font-wordmark` to `var(--font-sans)` under the attribute; turn on `font-optical-sizing: auto` and `font-variation-settings: "opsz" auto`; load Inter as a variable font with the `opsz` axis (`next/font/google` `Inter({ axes: ["opsz"], variable: "--font-inter" })`).
4. Radii and shadows: `--ll-radius-card: 12px`, `--radius: .5rem` (8px controls), card shadow tokens `0 1px 0 rgb(26 26 26 / .07)`, dark `none`.
5. Chrome: add `.chrome` (`background: var(--chrome); backdrop-filter: saturate(180%) blur(20px)`) for the top bar, sidebar and tab bar only. Provide a solid fallback for `prefers-reduced-transparency` and for no `backdrop-filter` (`--chrome` and `--sidebar` resolve to opaque `#F5F5F7` and `#F4F4F6`; dark `#101012` and `#18181B`). Contrast was measured with the translucent values over the canvas, so the solid fallback only improves it.
6. Structural changes (metrics card instead of four tiles, no awning, segmented control, grouped list for phone quick actions, white pass card, black primary) hang off `[data-theme-style="clear"]`.
7. Decide where the theme is stored (per shop, per user, per device).

## 8. Open choices

1. **Black primary.** It is what both Shopify and Apple do, and it makes the one coloured thing on a screen (a badge or a link) stand out. The cost: no brand colour on the main action. A trade-coloured primary was rejected as it would bring the colour back.
2. **Canvas `#F5F5F7` versus Polaris `#F1F1F1`.** `#F5F5F7` is Apple's and slightly lighter; `#F1F1F1` is Shopify's and a touch heavier. Either passes; `#F5F5F7` was picked because white cards on it have a softer edge.
3. **Peak bar in ink versus blue.** Ink matches the black primary and keeps the screen monochrome; blue would match Polaris charts. Ink was picked; one-line change.
4. **Translucent chrome.** Three surfaces (sidebar, top bar, tab bar). If any is unwanted it falls back to opaque with no layout change.
5. **Greeting copy.** The v3.1 sun glyph is removed. "Good morning, Sofia" is kept as plain 26px text because it is the existing Today title and the brief says same copy; if "cutesy" includes the greeting itself, replace it with the date ("Wednesday, Oct 28") and move the visits sentence under it.
6. **Who picks the theme.** Per shop or per user.

**Design-system values (fetched, not recalled)**
- Polaris tokens: `@shopify/polaris-tokens` 9.4.2 `dist/css/styles.css` (light theme and `p-theme-dark-experimental`), fetched from [jsDelivr](https://cdn.jsdelivr.net/npm/@shopify/polaris-tokens@9.4.2/dist/css/styles.css). Values used: colours in section 2, `border-radius-200` 8 and `-300` 12, `border-width-025` 1, `shadow-100`, `space-100` to `-800`, `font-size-325` 13, `font-size-350` 14, font weights 450 / 550 / 650 / 700, font family stack. The Polaris documentation pages ([polaris.shopify.com/tokens](https://polaris.shopify.com/tokens) and the old polaris-react URLs) redirect or return little to a fetch tool, so the package CSS is the source.
- Apple HIG: [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Color](https://developer.apple.com/design/human-interface-guidelines/color) and [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), read from Apple's JSON for those pages. Used: macOS and iOS text-style size and leading tables (Title 1 26 / 32 macOS and 28 / 34 iOS, Body 13 / 16 macOS and 17 / 22 iOS, Footnote and Caption sizes), the SF tracking table (for example -0.43pt at 17pt, -0.15 at 14, -0.08 at 13, 0 at 12), the colour guidance (apply colour to the background of a prominent primary action only; use system colours; test increased contrast) and the Materials guidance (materials on the navigation layer such as sidebars and tab bars; "Don't use Liquid Glass in the content layer"). The system colour table in the HIG page is images, so Apple's blue, grey and label values are taken from apple.com's own CSS instead.
- apple.com: [apple.com/mac](https://www.apple.com/mac/) stylesheets, read for `#f5f5f7` (page grey), `#1d1d1f` (text), `#86868b` and `#6e6e73` (secondary greys), `#d2d2d7` (hairline), `#0071e3` (focus and button blue), `#0066cc` (link blue), 12 and 10 px radii, `font-family: SF Pro Text, SF Pro Icons, Helvetica Neue, Helvetica, Arial`.

Nothing was copied from any reference; they set conventions. No Pinterest research was done in this revision because the brief asked for Mobbin and the design-system documents; Pinterest findings from rev 1 and rev 2 (a wall at signed-out search, most glass or neon pins being the opposite of this brief) are in `scratchpad/clear/patterns.md` and `v2/patterns-glass.md`.
