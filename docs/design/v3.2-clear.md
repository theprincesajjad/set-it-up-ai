Owner: Design. Status: **proposal for founder review, 2026-10-28**. Nothing in this change touches app code. It is a second theme over the same structure as v3.1 Main Street Warm: same shell, same Today cards, same pages, same copy.

**Brief (founder):** "have a clearer modern theme made as well that's not this colourful. Check out web-apps in dashboards on Mobbin and also use Pinterest and see dashboards for UI Ideas."

**Figma:** [Local Loyalty v3 design system](https://www.figma.com/design/tat1lWRQIJ2Q3Al98pWOtA), page **v3.2 Clear theme** ([page link](https://www.figma.com/design/tat1lWRQIJ2Q3Al98pWOtA?node-id=41-2)). The page has a `Clear / Color` variable collection with Light and Dark modes; every fill and stroke in the frames is bound to it, and the dark Today frame is the light frame in the Dark mode. Text is editable Inter text and icons are Lucide vectors.

## 1. The direction

Warm answers "everything looks so bland" with colour. Clear answers the follow-up "not this colourful" by taking colour out of decoration and keeping it only where it means something.

- **Surfaces are near-white.** Canvas `#FAFAFB`, cards `#FFFFFF`, a 1px cool-grey hairline, no card shadow. Only things that float (the customer sheet, menus, dialogs) get a shadow.
- **One accent.** Indigo `#2F5BEA` for the single primary action on a screen, links, the selected increment on the counter, and the "reward ready" state. Nothing else is coloured.
- **Colour means status.** Green for "can text", "live", "up vs last week". Amber and red are reserved for warnings and destructive actions. A neutral grey pill is used for counts, so "3 need you" does not read as an alarm.
- **Trade colour is a mark, not a surface.** The café family colour appears as an 8px dot after the shop name and as the one highlighted bar in "Visits by hour". On the pass it is the dot on the next stamp. In the "Nearby" list each shop has its own 8px dot. No tile, header, gradient or button takes a trade colour.
- **Inter, one family.** See section 3.
- **Same four Today stats, one strip.** Warm shows four pastel tiles; Clear shows the same four numbers as one card divided by hairlines (the pattern in Vercel, Shopify and Browserbase).

What Clear removes from Warm: the awning stripe, the serif display face, the pastel tile fills, the coloured Quick action tiles, the terracotta glow under the primary button, the trade-coloured pass gradient, the 22px card radius.

What stays identical: the sidebar items and order, the top bar, every label and number on Today, the "Needs you" rows and their buttons, the page order, the counter flow, the pass content.

## 3. Type

**Inter for everything.** Reasons: it is already the body font (`--font-inter`), so Clear adds no font download; it has real tabular figures (`tnum`) and a single-storey `a` option (`cv11`) that suits dense tables and counters; it renders the Latin side of mixed Urdu, Hindi and Punjabi lines, and the existing `SCRIPT_FONTS` fallback stack already hangs Devanagari, Gurmukhi, Nastaliq and Naskh behind it. Geist was the alternative: it looks similar but has no Indic or Arabic-script coverage and would add a second family to load for no visible gain.

Clear sets `--font-display` to the same stack as `--font-sans`, and `--font-wordmark` to the same, so every place that asks for Fraunces or Bricolage gets Inter.

| Style | Spec |
| --- | --- |
| Page title | Inter 600, 22 / 29, tracking -1.5%. (Warm: Fraunces 34.) |
| Card title | Inter 600, 14 / 20 |
| Stat value | Inter 600, 28 / 34, tracking -2.5%, `tnum` (26 in the 2x2 phone grid) |
| Counter numeral | Inter 600, 88 / 92, tracking -4%, `tnum` |
| Pass numeral | Inter 600, 36 / 40, tracking -3%, `tnum` |
| Row title, nav item | Inter 500, 14 / 20 and 13.5 / 18 |
| Body, table cell | Inter 400, 13.5 / 18 to 20 |
| Meta | Inter 400, 12.5 / 18, `muted-foreground` |
| Pill, chip | Inter 500, 12 and 13 |
| Group label | Inter 500, 11.5, `subtle-foreground`, sentence case (Warm: caps, +8%) |

`font-feature-settings: "cv11", "ss03"` on body; `font-variant-numeric: tabular-nums` on every number that changes (stats, table counts, times, stamps, keypad). Weights used: 400, 500, 600 only. Figma cannot set tabular figures through its plugin API, so the Figma frames show Inter's default figures; the HTML mock sets `tnum`.

## 6. Dark mode

Same roles, values in the tables above. Rules: canvas `#0A0B0D` and cards `#121316` differ by a few percent, so the 1px `--border` carries the structure; the primary is lifted to `#7391FF` and takes near-black text (6.77:1) rather than white (2.91:1); success, warning and destructive are lifted so their text passes 4.5:1 on the card; the pass card is `#1A1C21` so it separates from the card behind it. `data-theme="dark"` and the `prefers-color-scheme` guard work exactly as they do for Warm; Clear only adds the `data-theme-style` selector in front.

## 7. Urdu and RTL

The mock renders café Today in Urdu at 390 and 1440 (`clear-today-ur-390.png`, `clear-today-ur-1440.png`) with `dir="rtl"`. What it relies on, and what the build team should keep:

- **Logical properties everywhere.** `padding-inline`, `margin-inline-start`, `inset-inline-end`, `border-inline-end`, `text-align: start`. No `left` or `right` in themed CSS. Flex and grid then mirror by themselves: the sidebar goes to the right, the "Needs you" button moves to the inline start, the stat strip reads right to left.
- **Directional icons flip** (`chevron-right`, `arrow-*`): use `[dir=rtl] .flip { transform: scaleX(-1) }`. Neutral icons (search, bell, gift) do not flip.
- **Sparklines and the hour chart mirror** with the page, as in Warm (7 a.m. at the right edge in RTL). The mock mirrors sparklines with `scaleX(-1)` and lets the bar row reverse through flex. Numerals stay Latin digits, as in Warm.
- **Bidi islands.** Latin names inside Urdu lines (`Pinecone Coffee Co.`, `412 Roncesvalles`, `4 / 5`) need `<bdi>` or `dir="ltr"`; without it the trailing full stop and the number order flip. Applied in the mock.
- **Nastaliq needs height.** Body line height 1.95 (the v3 audit found clipped rows at tighter values). No fixed heights on rows or pills in Urdu: use `min-height` and padding. Inter is first in the font stack so digits and Latin letters stay Inter; Urdu letters fall through to Noto Nastaliq Urdu. Urdu body text reads small at 14px in Nastaliq; use 15px body and 13.5px meta when `lang="ur"` (the mock leaves it at 14 so the layouts are comparable; the 1440 render is still legible).
- **Urdu strings in the mock** reuse the v3.1 translations where they exist; strings new to Clear (for example "QR کٹ پرنٹ کریں") were written for the mock and need a native review before they ship.

Known gap in the mock: the Urdu render covers Today only. The customer sheet should open from the inline-end side (the left in RTL); the CSS above makes it do so.

## 8. Switching themes in the build

Add a `data-theme-style` attribute on `<html>` (default absent = Warm; `"clear"` = Clear). Light/dark stays on `data-theme`. In `packages/design-tokens` (build team, not part of this change):

1. New `src/clear.ts` beside `warm.ts` holding the values in section 2 as `clear` and `clearTiles`, and a `clearTradeColors(family, theme)` that returns `{ accent, foreground, alt: accent, soft, deep, passFrom: pass, passTo: pass, passText }`.
2. In `css.ts` emit a third block set under `:root[data-theme-style="clear"]` for light and the two dark selectors (`:root[data-theme-style="clear"]:not([data-theme="light"])` inside the media query, and `:root[data-theme-style="clear"][data-theme="dark"]`), plus the 14 `[data-trade="..."]` rules scoped the same way. Specificity: the `data-theme-style` attribute selector sits in front, so it beats the Warm `:root` rules without `!important`.
3. Override the font variables: `:root[data-theme-style="clear"] { --font-display: var(--font-sans); --font-wordmark: var(--font-sans); }`, and `--radius` to `0.625rem` (10px) with `--ll-radius-card: 10px`, `--ll-radius-tile: 8px`.
4. Shadows: `--ll-shadow-card` and the other card shadows to `none`; add `--shadow-float`.
5. Component changes that are structural rather than token-only (the stat strip, no awning, Quick action cards, active nav fill, table header) are listed in section 5 and should hang off `[data-theme-style="clear"]` or a `clear:` Tailwind variant so Warm is untouched.
6. A user setting or a `?theme=clear` query for review is enough to start; where the choice is stored (per shop, per user, per device) is an open product question below.

## 9. Open choices (need a decision)

1. **Accent hue.** Indigo `#2F5BEA`. It reads as software, does not collide with status green or red, and passes AA. A neutral-black primary (Fresha, Sweatpals) is more austere but disappears in dark mode and removes the one place colour is allowed.
2. **Chart highlight in the trade colour.** It keeps a small piece of each trade's identity; the cost is two hues on screen (indigo button, brown bar for a café). If that reads as noisy, switch the highlight to `--foreground` and keep the trade colour to the dot only.
3. **Pass card is near-black in light mode.** It reads as a card object and keeps the pass neutral. A white pass with a hairline is quieter but loses contrast against the canvas.
4. **Tablet counter layout.** The tablet shows keypad and customer side by side. In the app these are two steps; the two-pane arrangement is a layout adaptation for 1180 wide, not a change to the flow.
5. **Who picks the theme.** Per shop (the owner sets it for all staff) or per user.
