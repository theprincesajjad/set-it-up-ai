Owner: Design. Status: **proposal for founder review, 2026-10-28, revision 4**. Nothing in this change touches app code. Clear is a second theme over the same structure as v3.1 Main Street Warm: same shell, same Today cards, same pages, same copy.

## 1. The direction

**What Liquid Glass is** (sources in section 9). Apple's newsroom: it is "a new material" that "dynamically adapts" and "behaves like glass in the real world"; HIG Materials: it "forms a distinct functional layer for controls and navigation elements" that "floats above the content layer", and it "unifies the design language across platforms". WWDC25 session 219 lists the behaviours we copy:

1. **Lensing.** It bends and concentrates light behind it instead of only scattering it (refraction at the edge, a clear centre). Web: SVG displacement map.
2. **Specular edge highlights** that run around the rim, brightest top-left, with a faint return at the bottom-right. Web: masked gradient ring plus inset highlights.
3. **Adaptive tint and shadow.** It reads the content behind it; the shadow gets stronger when it floats over text. Web: fixed light and dark fills, tuned so contrast holds on the worst content behind them.
4. **Floating capsule tab bar and toolbar** that shrink when content scrolls and expand when it scrolls back. Web: `.min` class driven by scroll.
5. **Concentric corners.** Inner radius equals outer radius minus padding (sidebar 30, nav pill 17, toolbar 26, search 17, sheet 32, sheet cards 18).
6. **Glass-pane sheets and popovers** that sit on a dimmed content layer, not on a solid panel.
7. **Controls that lift** into brighter glass when selected (segmented control, selected nav item, selected tab) and morph between states.
8. **Content layer and glass layer stay separate.** HIG: "Don't use Liquid Glass in the content layer", use it sparingly, and honour Reduce Transparency and Reduce Motion. So cards, tables and charts stay flat Polaris white; glass is only the sidebar, toolbar, tab bar, sheets, popovers, segmented controls, secondary buttons, the pass card and the counter's two bars.

**From Shopify (Polaris):** white cards with a 1px hairline and a 1px shadow, dense card headers and row rhythm, index tables with checkboxes, black primary button, small crisp badges, bottom-centre toasts. Values in section 2 are Polaris's tokens.

**Something real sits behind the glass.** The scrolled Today cards and the metrics row pass under the toolbar and tab bar; the customers table and chart pass under the sidebar and the sheet; the map is a real OSM tile image behind the search capsule and bottom sheet; the pass card sits over the shop's own brand colour. No decorative gradient mesh anywhere.

**Still banned:** purple or indigo backdrops, neon, glows, sparkle icons, emoji, gradient text, meaningless sparklines, hero areas, stock illustration. The only gradient in the system is the 1.5px specular rim on glass edges, which is part of the material.

**Primary buttons are solid** (black in light, white in dark). Secondary buttons are glass (`--lg-seg-track` fill, inner highlight).

Glass recipe: `background: var(--lg-fill); backdrop-filter: blur(var(--lg-blur)) saturate(var(--lg-sat)); box-shadow: inset 0 0 0 1px var(--lg-edge), inset 2px 3px 6px -2px var(--lg-inner), inset -2px -3px 8px -4px var(--lg-inner), inset 0 0 22px var(--lg-inner), var(--lg-shadow);` plus a `::before` ring: `padding:1.5px; background: linear-gradient(140deg, rim-a 0%, rim-b 28%, transparent 52%, rim-b 74%, rim-c 100%)` masked to the border box with `mask-composite: xor`.

**Refraction (Chromium only).** For each glass element a script draws a displacement map on a canvas (a rounded-rect signed-distance field with a convex bezel profile, so the edge band bends the backdrop and the centre stays clear), puts it in an SVG filter `feImage -> feDisplacementMap (R and G) -> feGaussianBlur -> feColorMatrix saturate`, and sets `backdrop-filter: url(#filter) blur(8px or 10px)`. Displacement scale is about 1.6 to 1.8 times the bezel width. Safari and Firefox ignore `url()` in `backdrop-filter`, so the script is skipped and the element keeps plain `blur() saturate()`: same material without the lens. This is a progressive enhancement; the mock renders a no-refraction PNG to show the fallback is acceptable.

**Reduced transparency and motion.** `@media (prefers-reduced-transparency: reduce)` swaps every glass role for opaque values (light fill `#F2F2F4`, strong `#F7F7F9`, lift `#FFFFFF`; dark `#242427`, `#1F1F22`, `#3A3A3C`), sets blur to 0 and the rim and inner highlights to transparent, which leaves a flat Polaris-like surface with the same layout. The `.solid` class does the same for browsers without the media query. `prefers-reduced-motion` disables the tab-bar minimise animation, the lift transitions and popover scale; state still changes, instantly.

**Performance budget.** Each glass element costs a backdrop read. Rules: no glass in table rows, cards or charts; at most about eight glass layers on screen (Today desktop: sidebar, toolbar, four small buttons and the segmented control); filters are built once per element, not per frame; the **counter uses only two glass bars (top and bottom) with flat blur and no refraction** (`data-flat`), so scanning stays fast on a tablet.

## 2.9 Contrast on glass (measured)

Method (`contrast.js`, `cc.py`): render the screen, hide only the text and icons inside each glass element, sample the pixels actually behind them (including real content under the glass, such as table text, chart bars, map tiles and the brand-colour field), then compute WCAG 2.x contrast of the real foreground colour against the darkest and lightest sample. All glass text and icon pairs in both themes, Today 1440 and 390, customers, counter, pass, map and Urdu pass AA (4.5:1 for text, 3:1 for icons and large text) after the changes below. The raw per-element results are in `cc/*.json` and `cc/*.png`. Fixes made from the measurements: dark fills raised to `.60` and `.88`; light muted text darkened to `#54545A`; dark muted `#B4B4BA`; the sheet search field and sheet cards made solid-ish; the active tab label colour changed in dark. Known false positives: the SP avatar, "Ctrl K" and a few toolbar items on the customers screens sit under the dimming scrim in the render, so the sampler reads them against a darker region than the one a user sees; they pass when the scrim is excluded.

## 3. Type

**Inter, with the display optical size for titles.** Reasons: Inter is the closest free match to SF Pro (a neutral grotesk with the same proportions and a variable optical-size axis that plays the role of SF Display versus Text); Shopify's admin uses Inter (the Polaris font stack is `'Inter', -apple-system, BlinkMacSystemFont, 'San Francisco', ...`), so users of both already read it; it is already the app body font (`--font-inter`), so there is nothing new to download; it has tabular figures (`tnum`), which the stat numbers, table counts, times and keypad need; and the existing Noto fallbacks for Hindi, Punjabi and Urdu keep following it. Geist was compared side by side with Inter on Today (`clear-font-compare.png`); at this density the two are almost the same, and Geist has no Indic or Arabic-script coverage. Plus Jakarta Sans (rev 2) is dropped: it is rounder and softer, which is the opposite of precise.

Inter's variable `opsz` axis (14 to 32) is switched on (`font-optical-sizing: auto`), so text sizes get the text cut and 26px titles get the display cut. Weights follow Polaris's variable-font values: regular 450, medium 550, semibold 650, bold 700 (`font-weight-regular: 450` and so on in Polaris tokens), so `font-weight: 450 / 550 / 650` in CSS (400 / 500 / 600 where the font is static). Letter-spacing follows SF's own tracking table (HIG Typography): -0.022em at 26px, -0.014em at 17, -0.011em at 14, -0.006em at 13, 0 at 12.

## 4. Components

- **Card with title and actions** (Polaris): white, 12 radius, 1px `--border`, 1px shadow; header 14 / 16 padding with the title left and an action (a segmented control, a text link or a slim button) right; rows divided by hairlines, not by space.
- **Metrics card:** one card, four cells divided by hairlines; label (13, 550, muted), number (26, 650), caption (12, 550; green only when it is an increase). No sparklines.
- **Index table** (Polaris IndexTable): toolbar with a segmented control (All 67, Regulars 30, ...) and Search, Filter, Sort buttons; a bulk-action bar that replaces nothing but sits under the toolbar when rows are selected (a mixed checkbox, "1 selected", Text, Add stamp, More actions); header row 12 / 550 muted on a hover-tint fill; 52px rows; checkbox column 44; selected row tinted `--row-sel`; hover row tinted `--accent`; badges for status; no avatars-with-colour (initials on grey).
- **Badges** (Polaris): 20px high, 8 radius, 12 / 550, no dot; neutral (grey), info (blue tint), success (green), warning (amber), critical (red). "Can text", "Live", "Reward ready", "Reward".
- **Segmented control** (Apple): `--seg-track`, 9 radius, selected segment white with a 1px shadow; used for Today / Week, the customer filters and the counter increments (larger).
- **Sheet:** 440 wide, flush to the right edge, `--background` body with white cards inside (like Shopify's customer detail page, in a drawer), flat 20% scrim with no blur, `--shadow-float`.
- **Toast** (Polaris): dark `#303030` rounded-8 bar, 13 / 550 text, an "Undo" action and a close icon, bottom centre of the content area.
- **Empty state** (Polaris): inside a card, a 40px grey icon chip, a 16 / 600 title, one sentence of concrete advice, a primary and a secondary button, a "Learn more" link below the card (`clear-empty-state-1440.png`, Promos).
- **Primary button:** black, 8 radius, no shadow; in dark it is white with black text. **Secondary:** white, 1px `--border-strong`, 1px shadow.
- **Phone tab bar** (iOS): translucent `--chrome`, 1px top border, 24px icons, 10px labels, the active tab in `--link`. This is one of the three translucent surfaces.
- **Pass** (Apple Wallet): a white card, 12 radius; top row with the shop mark (trade colour), the name and a "2 to go" badge; two rows of ten-stamp circles, filled in trade colour with a white coffee glyph, the next stamp a trade-coloured ring with a dot, empty stamps a hairline ring; below a hairline, three labelled fields (STAMPS, NEXT REWARD, MEMBER SINCE) in the Wallet field style. No gradient, no shadow.
- **Counter:** a solid, flat screen: white left panel with the phone field and keypad (white keys, 1px hairline, 1px shadow), the stamp card on the grey canvas, black primary buttons at 56px high. No translucency anywhere on the counter except the header, which uses `--chrome` as a flat fill.

## 7. Switching themes in the build

`data-theme-style` attribute on `<html>` (absent means Warm; `"clear"` means Clear); light and dark stay on `data-theme`. In `packages/design-tokens` (build team, not part of this change):

1. New `src/clear.ts` beside `warm.ts` holding the values in section 2 and `clearTradeColors(family, theme)` returning `{ accent, foreground, alt: accent, soft: muted, deep: accent }`.
2. In `css.ts` emit the third block set under `:root[data-theme-style="clear"]` for light and the two dark selectors, plus the 14 `[data-trade]` rules scoped the same way. The attribute selector sits in front, so it beats Warm without `!important`.
3. Fonts: leave `--font-sans` as Inter; set `--font-display` and `--font-wordmark` to `var(--font-sans)` under the attribute; turn on `font-optical-sizing: auto` and `font-variation-settings: "opsz" auto`; load Inter as a variable font with the `opsz` axis (`next/font/google` `Inter({ axes: ["opsz"], variable: "--font-inter" })`).
4. Radii and shadows: `--ll-radius-card: 12px`, `--radius: .5rem` (8px controls), card shadow tokens `0 1px 0 rgb(26 26 26 / .07)`, dark `none`.
5. Chrome: add `.chrome` (`background: var(--chrome); backdrop-filter: saturate(180%) blur(20px)`) for the top bar, sidebar and tab bar only. Provide a solid fallback for `prefers-reduced-transparency` and for no `backdrop-filter` (`--chrome` and `--sidebar` resolve to opaque `#F5F5F7` and `#F4F4F6`; dark `#101012` and `#18181B`). Contrast was measured with the translucent values over the canvas, so the solid fallback only improves it.
6. Structural changes (metrics card instead of four tiles, no awning, segmented control, grouped list for phone quick actions, white pass card, black primary) hang off `[data-theme-style="clear"]`.
7. Decide where the theme is stored (per shop, per user, per device).

## 8. Open choices

1. **Black primary.** It is what both Shopify and Apple do, and it makes the one coloured thing on a screen (a badge or a link) stand out. The cost: no brand colour on the main action. A trade-coloured primary was rejected as it would bring the colour back.
2. **Canvas `#F5F5F7` versus Polaris `#F1F1F1`.** `#F5F5F7` is Apple's and slightly lighter; `#F1F1F1` is Shopify's and a touch heavier. Either passes; `#F5F5F7` was picked because white cards on it have a softer edge.
3. **Peak bar in ink versus blue.** Ink matches the black primary and keeps the screen monochrome; blue would match Polaris charts. Ink was picked; one-line change.
4. **Glass chrome (rev 4).** Glass is on the sidebar, toolbar, tab bar, sheets, popovers, segmented controls, secondary buttons, pass card and the counter's two bars. Any surface falls back to opaque through the reduced-transparency roles with no layout change. Open: whether the floating sidebar should carry glass at all, since little sits behind it on a plain canvas; it is kept for the Apple floating-sidebar look.
4a. **Refraction is Chromium only.** Safari and Firefox get blur and saturation without the lens. Accept, or ship blur-only everywhere for consistency.
4b. **Map tiles.** OSM tiles require the visible attribution (kept in the mock). The dark map is a filtered OSM tile; production should use a proper dark style. The shop pins in the mock are fictional.
4c. **Font.** Inter with `font-optical-sizing: auto` (display cuts at large sizes, tracking per the HIG table); Geist remains an alternative via `&f=geist` in the v3 mock.
5. **Greeting copy.** The v3.1 sun glyph is removed. "Good morning, Sofia" is kept as plain 26px text because it is the existing Today title and the brief says same copy; if "cutesy" includes the greeting itself, replace it with the date ("Wednesday, Oct 28") and move the visits sentence under it.
6. **Who picks the theme.** Per shop or per user.
