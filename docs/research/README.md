# Industry research and design briefs

One file per market. Each is written by a team acting as an expert in that market and is the reason the
modules, screens and components look and work the way they do. Format for every brief:

1. **Who this is for** — the businesses (size, staff, tools they use today, what they pay for them) and their customers in the GTA.
2. **Evidence** — sources (with links), competitor pricing and features, local facts (by-laws, tax, payment habits, languages).
3. **Jobs to be done** — the 5–10 jobs the owner, staff and customer hire us for, ranked by frequency × pain.
4. **What we build and why** — each module/screen/component mapped to a job; anything that maps to no job is cut.
5. **What we deliberately don't build** — and why.
6. **Design** — the Figma file link and frame list, the Mobbin references used (with links) and what each taught us.
7. **Build spec** — concrete changes to the existing code (files, endpoints, components), acceptance checks.
